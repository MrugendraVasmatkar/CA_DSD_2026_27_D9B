# Digital System Design (DSD) — Continuous Assessment Submissions

The problem statements have already been provided separately. Each group must use its allotted problem statement and submit the required work in the relevant CA folder.

## Assessment folders

| Folder | Submission |
|---|---|
| `CA1/` | Problem understanding, architecture, FSM/datapath design and Logisim evidence |
| `CA2/` | Verilog RTL, testbench and simulation/verification evidence |
| `CA3/` | FPGA implementation, hardware demonstration and final results |

Read the `README.md` inside each CA folder before uploading work.

## Create a group repository using Fork

1. Open the faculty's original DSD CA repository on GitHub.
2. Click **Fork** and select the student's GitHub account.
3. Give the fork a group-specific name, for example `DSD-CA-D9A-Group-01`.
4. The group leader opens the fork and goes to **Settings → Collaborators** to invite the other group members.
5. Each member accepts the invitation using their own GitHub account. Do not share passwords.
6. Clone the group's fork using GitHub Desktop, or use **Code → Download ZIP**.
7. Keep the `CA1`, `CA2` and `CA3` folder names unchanged. Add each assessment's files to its matching folder.
8. Commit and push updates regularly. Example commit messages: `CA1: add FSM diagram`, `CA2: upload testbench`, `CA3: add FPGA results`.
9. Check the online repository before submitting and share the URL of the group's forked repository through the faculty-announced submission method.

## Upload files through GitHub website

1. Open the group's forked repository and select the relevant folder (for example, `CA1`).
2. Select **Add file → Upload files**.
3. Drag files/folders from File Explorer into the upload area, or select files.
4. Enter a meaningful commit message and select **Commit changes**.

For repeated updates or many files, GitHub Desktop is recommended: clone the fork, copy files into the appropriate CA folder, commit, then select **Push origin**.

## Important

- Use one forked repository per group, not a separate repository for each CA.
- Do not delete or rename the CA folders or instruction files.
- Upload source/design files as well as supporting screenshots and reports.
- Keep the repository visibility as instructed by the faculty.
- All members should contribute and understand the submitted work.
